# Оценка задач с обучением на факте

Оценка «на глаз» ошибается в разы. Своих часов у меня нет: 20.10 оценка 10–18 ч вышла при факте ≈ 3 ч. Поэтому
прогноз строится по аналогам из журнала, а факт меряет скрипт по журналам сессий.

## 0. Журнал и единица
- **Журнал** — `projects/<имя>/memory/estimates.md`: подняться от текущей директории до `projects/<имя>/`, как в
  `wind-down`. Журнала нет — скопировать `templates/project/memory/estimates.md`. Журнал локальный: ключи и
  названия задач рабочих проектов в git хаба и наружу не уходят.
- **Единица** — моё **активное** время от взятия задачи до доклада «готово к пушу»: чтение, код, тесты, ревью,
  браузер, скриншоты. Ожидание ответов пользователя считается отдельной цифрой и в прогноз не входит.
  Человеко-часы (ERP, клиент) — другая единица: давать их, только если попросили, отдельной строкой с пометкой.
- **Скрипты** (`node`, из Bash): факт — `${CLAUDE_SKILL_DIR}/scripts/session-time.cjs`, поправки —
  `${CLAUDE_SKILL_DIR}/scripts/corrections.cjs`. Тесты: `node --test ${CLAUDE_SKILL_DIR}/scripts/`.
- **Метки** `⏱ EST-START/END <KEY>` ловит модуль Stop хаба (`estimate-marks`, стадия по проекту): метки хода — в
  тексте, в сообщениях диспетчеру, в последнем сообщении — пишутся в индекс `projects/<имя>/memory/est-marks.jsonl`,
  по нему `session-time.cjs key` идёт прямо в журналы задачи. Индекс не править руками.

## 1. Прогноз — `estimate <KEY…>`
1. Задачу прочитать полностью, по правилам проекта. Признаки проверить в коде (можно силами разведчика), а не
   по тексту задачи.
2. Прочитать журнал: «Поправки», «Якоря шкалы», а также 2–3 закрытые задачи с похожими признаками и их факт.
   Это основа прогноза.
3. Разложить на шаги **в своём темпе**: бэк с тестами, генерация клиента, фронт с тестами, ревью, браузер и
   доказательства, ответы по развилкам. Сложить шаги, сверить с аналогами. Цифру субагента как есть не пересылать:
   пересчитать по шагам.
4. **Поправку применяет скрипт, не глаз:** `node ${CLAUDE_SKILL_DIR}/scripts/corrections.cjs <журнал> --apply
   <мин>–<макс> --complexity <N>` — диапазон по шагам × множитель класса сложности (или общий). Он и есть прогноз;
   цифру по шагам — в «Аналоги» строкой «по шагам 40–75». Закрытых строк < 10 — скрипт пишет «поправки нет»:
   прогноз — по шагам и аналогам.
5. Поставить:
   - **сложность N/10** по якорям журнала;
   - **МР:** `1` или `N срезов` (сколько из них параллельно);
   - **признаки** — коды из легенды журнала;
   - **прогноз** — `мин–макс` активного времени;
   - **прогноз +20%** — те же границы × 1,2: запас на то, чего журналы сессий не видят (подготовка, переключения,
     проверки пользователя). Отдельным столбцом рядом с прогнозом, сам прогноз не заменяет;
   - **аналоги** — ключи задач, на которые опирался.
6. Записать строку в журнал **до работы**: дата из `date`, «Прогноз» и «Прогноз +20%», колонки факта пустые.
   Прогноз потом не править. Новые вводные (ответ на развилку, отказ от варианта) — новая строка
   `<KEY> (пересмотр)` с причиной.
7. Пользователю показать таблицу от меньшей задачи к большей, со столбцами «Прогноз» и «Прогноз +20%». Под каждой —
   развилки, которые двигают максимум.
8. **Метка старта.** Работа над задачей начинается в этой сессии — отдельной строкой ответа написать
   `⏱ EST-START <KEY>`. Только оценка без работы — без метки: её ставит та сессия, что возьмёт задачу. Сессия
   задачи под диспетчером ставит метку сама в первом сообщении.

## 2. Факт — `estimate close <KEY>`
Вызывается при докладе «готово к пушу», в конце раунда (ревью, ребейз) и из `wind-down`, если в сессии есть
`EST-START` без `EST-END`.
1. Отдельной строкой ответа написать `⏱ EST-END <KEY>`, а уже потом запустить скрипт:
   `node <скрипт> key <KEY>` из папки проекта или worktree. Он сложит все раунды по ключу во всех сессиях; последняя
   строка — откуда журналы: `source: marks` (индекс меток) или `scan` (все журналы; ключа нет в индексе — например,
   модуль в проекте выключен). Раунд после доклада начинается новой `⏱ EST-START <KEY>`. Сессия в worktree без
   меток — `node <скрипт> dir '<папка worktree>'`.
2. Заполнить колонку «Факт»: `активно / ожидание`, число раундов. Строка без END — пометить «без END». Колонку
   «Факт +20%» — активное × 1,2: скрипт печатает его рядом (`active 48 min  +20% 58 min`). Пользователю — обе цифры.
3. **Попал или нет:** по реальным цифрам, без запаса: факт внутри `мин–макс` прогноза — «да». Иначе —
   `×<факт ÷ середина прогноза>` и **одна причина** из
   списка:
   - `объём` — шагов больше или меньше, чем думал;
   - `развилки` — ответы, переделки после ответа;
   - `окружение` — генерация, миграции, партии тестов, дев-стенд;
   - `ревью` — круги ревью и правки после него;
   - `доказательства` — браузер, скриншоты, playwright;
   - `чужое` — CI, деплой, доступы;
   - `темп` — шаги верны, но каждый шёл дольше или быстрее.

   Добавить короткое «почему»: какой шаг недооценил. Отдельно отметить признак, который оказался другим
   (например, «миграция не понадобилась»).
4. Промах больше чем в 2 раза — правило в `memory/errors.md` проекта (и строкой в индекс), чтобы в следующий раз
   учесть.

## 3. Обучение — `estimate review`
Раз в 10 закрытых строк (`wind-down` напоминает) или по просьбе:
1. Множители считает скрипт: `node ${CLAUDE_SKILL_DIR}/scripts/corrections.cjs <журнал>` — медиана
   `факт ÷ середина прогноза` по закрытым строкам (без «ретро» и отменённых), в целом и по сложности 1–3 / 4–6 /
   7–10 (класс — от 3 строк). Признаки (миграция, новые ручки, DnD, развилки ≥ 2) — глазами по строкам, словами.
2. Переписать «Поправки» выводом скрипта: множители, N, дата, частые причины. Закрытых строк меньше 10 — скрипт
   пишет «поправки нет»: так и записать, опора — аналоги.
3. Обновить «Якоря шкалы»: по одной реальной задаче с фактом на 2, 4, 6 и 8 баллов. Если якорь сдвинулся —
   прежний оставить строкой `было: …`.
4. Итог показать пользователю: что поменялось и где промахиваюсь чаще всего.
5. Сразу после — скилл `memory-gc` (уборка памяти проекта), он тоже раз в 10 задач.

## Засев журнала прошлыми задачами
Для worktree-сессий — `dir '<папка worktree>'`. Для общей папки — `file <журнал>` по сессиям, где ключ виден в
`memory/sessions/`. Сложность и признаки ставятся задним числом с пометкой «ретро» в колонке «Прогноз». Такие
строки годятся в якоря и аналоги, но в медиану промахов не идут.
