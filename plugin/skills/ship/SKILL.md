# ship — довести до «готово к пушу» без пинков

Начинай, когда реализация закоммичена. Между шагами пользователя не жди: единственная остановка — шаг 8.
Сессия задачи под диспетчером (бриф «Ты — сессия задачи…» или cwd в `projects/*/worktrees/*`) этот скилл не
зовёт: доклад по брифу, пушит диспетчер.

**Три точки паузы** — после шагов 4 (`checks`), 3 (`review`) и 5 (`evidence`): на каждой 1–7 пунктов «объект →
наблюдение → подтверждение» в квитанцию `projects/<имя>/memory/<ветка>/ready.json` хаба. Подтверждение — след,
который сверит скрипт (лог прогона с HEAD, файл отчёта ревьюера, скрин, файл, коммит), формат —
`node ${CLAUDE_SKILL_DIR}/../dispatch/scripts/push-slice.cjs --help`. Увидел то, чего быть не должно (тесты
зелёные на пустом месте, чужие изменения в ветке, проверка хуже базы), — исход **«Остановлено: аномалия: <что>»**:
законный, квитанция с `"outcome": "anomaly"`, вместо шага 8 — вопрос пользователю, обходом не чинить.

1. **`checks`** — свои файлы. FAIL — чини и снова `checks`. Затем **самопроверка**: свой дифф глазами против
   критериев задачи, в коммитах только своё.
2. **Ревью** — subagent `hub:reviewer` по правилу 8 хаба: режим «полное», дифф ветки, критерии задачи, вывод `checks`;
   были красные коммиты — их sha и дифф тестов после них (тесты не подогнаны под код). Отчёт — файлом
   `memory/<ветка>/review-<круг>.md`: след точки `review`. `checks --full` можно гнать параллельно ревью.
3. **Правки по находкам:** CRITICAL/HIGH/MEDIUM — исправить (логика — по правилу 2 с красным тестом); LOW —
   правка без нового круга или пункт в описании MR. Правки задели логику — «проверка правок» (находки прошлого
   круга + sha), всего не больше 3 кругов. После 3-го осталось CRITICAL/HIGH — стоп, это вопрос пользователю
   (шаг 8 с вариантами «чинить дальше / пушить как есть / не пушить»); MEDIUM третьего круга — исправить и
   назвать в докладе как правку без ревью.
4. **`checks --full`** на итоговом HEAD — его строка с HEAD и числом коммитов идёт в доклад (срез цепочки —
   с `--base <ветка родителя>`). WARN «нет фона» — сказать в докладе. Лог прогона — след точки `checks`.
5. **Доказательство** по дорожке `fast-lane`: скрин или сценарий пробы; файлы скринов — по личным правилам
   пользователя (`CLAUDE.local.md`). Код менялся после пробы — в докладе одной строкой, нужен ли повтор и почему.
   Квитанция готова — `push-slice.cjs verify <repo> <ветка> --receipt <ready.json>`: печатает только расхождения;
   исправить до доклада.
6. **Оценка:** `estimate close <ключ>`, если задача её получила.
7. **Доклад одним сообщением:** что сделано (по пунктам задачи), HEAD и коммиты, цифры `checks --full`, итог
   ревью (круги, что исправлено, LOW в MR), скрины, расхождения квитанции, если остались, строки `риск: …`
   (CI, деплой, зависимости, сеть, секреты — их скрипт печатает в `push --dry-run`), **текст MR** (заголовок и описание — скилл MR, который
   назван в CLAUDE.md проекта; нет такого — коротко: ссылка на задачу, что изменилось, как проверить), что не
   проверено.
8. **Один `AskUserQuestion`.** Варианты — вид пуша по правилу проекта (например «пуш + draft MR» и «пуш
   `-o ci.skip` + draft MR») и «пока не пушить». Вариант не советуй, если правило проекта велит решать
   пользователю каждый раз. Есть `риск: …` — это в вопросе отдельной строкой, согласие на него — отдельный вариант.
9. **По ответу:** пуш скриптом — `node ${CLAUDE_SKILL_DIR}/../dispatch/scripts/push-slice.cjs push <repo> <ветка>
   <sha> --receipt <ready.json> --base <база> --solo` (+ `--risk-ok <категории>` по согласию на риск); голый
   `git push` в проектах хаба запрещает хук `bare-push`. Скрипт пушит без силы: после ребейза он откажет «не
   fast-forward» и назовёт вершину ветки на remote — замена ветки только по прямому ответу пользователя, флагом
   `--lease <эта вершина>` (как `--force-with-lease`: не заменит, если ветку за это время пушил кто-то ещё). Затем
   MR с текстом из шага 7, ссылка на MR. Ответ «не пушить» — стоп, ветка остаётся локально.
10. **`/hub:wind-down`** — итог сессии (сразу, если пользователь не дал новую задачу в этой сессии).

Не делать: не мержить, не снимать draft, не писать в трекер и треды без отдельной просьбы, не пушить при FAIL
`checks --full` — это сначала вопрос пользователю.
