# memory-gc — память растёт, а не пухнет

Папка проекта — `projects/<имя>/` хаба (подъём от cwd). Каждое изменение — сначала списком пользователю, одним
сообщением; делать после «да». Удалять нельзя: только перенос в `memory/archive/` или `memory/snippets/archive/`.

0. **Формат памяти** — по наличию `memory/lessons/`. Есть (память v2) — сначала шаги v2 ниже, затем 4–8; шаги 1–2 —
   только для старого формата (в v2 `errors.md` и `errors-index.md` — двойная запись и экспорт, их не чистят руками).
   Команда v2 — `node ${CLAUDE_SKILL_DIR}/scripts/gc.cjs <команда>` из папки проекта (или `--memory <папка memory>`):
   она только показывает, кроме `review`/`reviewed` (дозапись событий) и `fold --apply` (переписывает старые месяцы
   событий, исходник — в архив). Меняют уроки команды скилла `recall`
   (`node ${CLAUDE_SKILL_DIR}/../recall/scripts/recall.cjs …`) — после «да» пользователя, правки текста — Edit/Write.
   - **v2-а. Дубли:** `gc.cjs dups` — пары взаимно ближайших уроков с общими словами. Это одно и то же — Edit
     урока-приёмника (ничего из двух не теряется), затем `recall.cjs merge <из> <в>`.
   - **v2-б. Отставка по условию:** `gc.cjs retire [--days 30]` — правила без показа и повтора N дней (класс «одного
     раза» и ядро не уходят). После «да» — `recall.cjs retire <id> --note "<почему>"`: архив, не удаление.
   - **v2-в. Смена модели:** `gc.cjs review --model <id модели этой сессии>` — модель последних событий другая →
     все живые уроки ставятся на пересмотр (событие `review`, повторный вызов не дублирует). `gc.cjs review --list` —
     что ждёт; урок верен для новой модели — `gc.cjs reviewed <id>`, устарел — отставка (v2-б), неточен — Edit.
   - **v2-г. Свёртка событий:** `gc.cjs fold` — месяцы `memory/events/` старше 3: остаются все `repeat`, `merged`,
     `superseded`, `retired` и последний `shown` на урок; после «да» — `gc.cjs fold --apply`, исходный месяц побайтно —
     в `events/archive/` (не удаление). `shown` свёрнутого месяца значит «был показан в месяце», не сколько раз:
     действенность подачи считать по журналу подач, не по свёрнутым событиям памяти.
   - **Фразы пользователя** — командами `recall`: «что помнишь про X» — `find X`; «почему так решили» — `find
     <тема>` по решениям; «почему мне это подали» — `why <id>`; «забудь урок» — `retire <id>` (класс «одного раза» не
     уходит — скажи об этом).

1. **Индекс ошибок** (`memory/errors-index.md`): ≤ 150 строк, строка ≤ 160 знаков (бриф на старте сессии пишет
   нарушения). Длинное — короче, детали остаются в `errors.md`; близкие строки — слить; правило, которое теперь
   держит хук, — одной строкой «механизировано: <id>», а прежний текст строки — в `memory/archive/errors-index-*.md`.
   Индекс — выжимка, его правки не теряют знания: подробности всегда в `errors.md`.
2. **Уроки → механизм.** В `errors.md` записи с `повторов ≥ 2` и `механизм: нет` — предложить правило в
   `projects/<имя>/rules.json` (`id`, `tools`, `commands`/`path` — регэкспы, `text`, режим `log`).
3. **Журнал правил:** `node ${CLAUDE_SKILL_DIR}/../../hooks/journal-summary.cjs <папка проекта>`. Правило в `log`
   с частыми срабатываниями и без ложных (просмотреть `memory/rules-guard.log`) — предложить `"modes": {"<id>": "deny"}`;
   ложные срабатывания — поправить регэксп. Журнал больше 1 МБ — старое в архив.
4. **Ветки** (`memory/branches.md`): строки смерженных (`git cherry origin/main <ветка>` пуст) — в
   `memory/archive/branches-*.md`.
5. **Бэкапы мутантов:** в `.git` рабочего репо `mutants-pending.json.kept-*` / `.broken-*` — сверить с `git diff` и
   перенести в `memory/archive/` проекта.
6. **Сниппеты:** переиспользуемые (запускались в ≥ 2 задачах) — строкой в `memory/snippets/INDEX.md`;
   одноразовые старше 30 дней, не упомянутые в CLAUDE.md, recipes и INDEX, — в `memory/snippets/archive/`.
7. **Дубли:** правило и в CLAUDE.md проекта, и в индексе — оставить в одном месте (вторую копию — в архив) (CLAUDE.md — команды и
   устройство, индекс — запреты из ошибок). `decisions.md` дублирует durable-док репозитория — в записи ссылка.
8. **Итог** — что перенесено, что поднято до deny, сколько строк индекса и КБ памяти стало.

Отличие от встроенных: `consolidate-memory` работает только с авто-памятью Claude Code, `/doctor` — с
инструкциями; этот скилл — с памятью проекта хаба и журналом хуков.
