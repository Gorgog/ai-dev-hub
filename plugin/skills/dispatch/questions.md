# Диспетчер: вопросы и согласия

## 5. Вопросы, решения, согласия

- **Каждое решение пользователя — вопросом с вариантами** (`AskUserQuestion`), а не вопросом прозой в конце
  сообщения. Исключение — слово запуска, оно нужно текстом (§3).
- **Вопросы сессий** — собирать и приносить пользователю одним пакетом, у каждого вопроса — рекомендация сессии.
  В пилоте на 20 вопросов хватило одного ответа «рекомендации сессий». Больше 4 вопросов — списком текстом и
  вопрос «принять рекомендации / ответить по пунктам». Ответ передать сессии словами пользователя в кавычках. Сам за него не решать и не советовать там, где
  правило проекта это запрещает (вид пуша).
- **Согласия не передаются сообщением.** Claude Code не считает сообщение от другой сессии согласием
  пользователя. Пуш, MR, ответы в треды, запись в трекер и мутации дев-данных делаются одним из двух способов:
  - **(по умолчанию) делает диспетчер** по прямому ответу пользователя в своём чате:
    → шаги 1–6 — `push.md`.
  - **Пользователь отвечает прямо в сессии задачи.** Диспетчер даёт ссылку: `[заголовок](#local_<id>)`.
- **Модель ревью** — Opus из `reviewer.md` (правило 8 хаба); другую — только если пользователь назвал её сам. Выбор
  модели — не согласие, его можно передать сообщением.
