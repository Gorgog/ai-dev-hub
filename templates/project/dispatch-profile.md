# Профиль диспетчера — <имя проекта>

Читает скилл `dispatch` (`<хаб>/plugin/skills/dispatch/`). Здесь — только специфика проекта. Профиль лежит в
локальной папке проекта и в git хаба не входит.

## Скиллы
- Как называются в этой установке `workplan` и `grilling` (например, с префиксом плагина).
- **Запрещено сессиям задач:** <скиллы, которые сами пушат, создают MR или переключают ветки основной копии>.

## Пути
- repo: `<хаб>/projects/<имя>/repo`
- worktrees: `<хаб>/projects/<имя>/worktrees/<ветка>` (внутри проекта: CLAUDE.md хаба и проекта
  подгружаются сами). Имена веток короткие — `<KEY>-NN`.
- Создание: `bash <хаб>/plugin/skills/dispatch/scripts/wt-new.sh <repo> <worktrees> <ветка> <база> <env-файлы…>`
- Замер: `bash <хаб>/plugin/skills/dispatch/scripts/headroom.sh -Ports <порты> -Worktrees <хаб>/projects/<имя>/worktrees`
- Прогоны: `bash <хаб>/plugin/skills/dispatch/scripts/hub-run.sh --list`, погасить —
  `… hub-run.sh --stop <worktree>`
- Проверка конфликтов: `bash <хаб>/plugin/skills/dispatch/scripts/parallel-check.sh <repo> <родитель волны> <ветки…>`
- Уборка: `bash <хаб>/plugin/skills/dispatch/scripts/wt-remove.sh <repo> <worktree>`
- Доска: `memory/dispatch.md`

## Лимиты
- Сессий задач — до <N> (по умолчанию 7: до 5 свободно, 6–7 — с `headroom.sh -MinPhysGB 5`). Тяжёлое — одно на всех. Выдавать при коде 0 `headroom.sh` (запас: доступная память +
  свободный swap/zram ≥ <N> ГБ, PSI памяти ниже порогов); свой `-MinGB`/`-MinPhysGB` — если по умолчанию мало.

## Тестовая БД — выключено
Необязательный механизм: своя тестовая БД на каждый worktree, чтобы тесты двух сессий не ждали друг друга в
очереди за общей БД. Пока заголовок не ровно «## Тестовая БД», скрипты worktree работают как без него. Включён —
`wt-new.sh` создаёт БД из шаблона в уже запущенном тестовом контейнере, `wt-remove.sh` удаляет её, а тесты сессия
запускает обёрткой `bash <хаб>/plugin/skills/dispatch/scripts/wt-db.sh run <worktree> [-- <команда>]`: она
подставляет адрес своей БД в переменную окружения, остальное окружение не трогает (тяжёлые тесты — через
`hub-run.sh … -- bash …/wt-db.sh run …`). Файлы проекта не правятся.

**Включить:** заголовок → «## Тестовая БД», заглушки `<…>` в ключах ниже → значения (значение — первое `…` строки,
пояснение после него можно оставить). Ключ `тесты` — необязательный (команда по умолчанию для `wt-db.sh run`):
не нужен — удали строку, заглушку скрипт не примет. Префикс имён БД по умолчанию — `wt_<папка проекта>_`, свой —
строкой «префикс» в этом списке.

- контейнер: `<имя тестового контейнера postgres>` — должен быть запущен; скрипты его не создают и не
  останавливают
- пользователь: `<пользователь postgres с правом CREATEDB>`
- шаблон: `<БД-образец: схема и сиды уже применены>` — к ней не должно быть подключений дольше 5 с во время
  `wt-new.sh`
- переменная: `DATABASE_URL`
- адрес: `postgresql://<пользователь>:<пароль>@localhost:<порт>/{db}` — `{db}` заменяется именем БД worktree
- тесты: `<команда тестов из корня worktree>`

Имя БД = префикс + путь worktree от папки `worktrees` в `[a-z0-9_]` (до 63 знаков); два worktree с одним именем
или имя, равное шаблону, скрипт отклоняет. Каждая БД помечается проектом-владельцем (`COMMENT ON DATABASE`):
пересоздаёт, удаляет и отдаёт тестам скрипт только свои — БД того же имени у другого проекта или без метки
(создана руками) он не трогает, код 3. Метка — путь папки `worktrees`: переехал хаб — прежние БД стали чужими,
снять их руками (`DROP DATABASE`). Своя БД без живого worktree — сирота: диспетчер на старте снимает их
`wt-remove.sh --orphans <repo> <папка worktrees>` (посмотреть — `wt-db.sh orphans <repo> <папка>`).

Перед включением проверить (проба P4):
1. Загрузчик тестов не перекрывает переменную файлом: `dotenv` и `dotenv -e` без `override`/`-o` — env главнее
   `.env.test`; перекрывает — не включать, вопрос пользователю.
2. Команда тестов не пересоздаёт контейнер (`docker compose down -v` уносит БД всех worktree) и не применяет
   миграции к общей БД.
3. Подключения: прогонов × подключений на прогон ≤ `max_connections` − 3; не влезает — тесты под очередью тяжёлого.
4. Ветка с новыми миграциями применяет их к своей БД сама (команда миграций через `wt-db.sh run`).

**Выключить:** сначала `wt-db.sh drop <worktree>` для каждого живого worktree и `wt-remove.sh --orphans`, потом
заголовок обратно в «— выключено» (после этого скрипты БД не видят и не удалят). Срочно — сразу заголовок: тесты
пойдут на общую БД из `.env.test`, оставшиеся БД `wt_…` снять позже, включив раздел на время уборки.
