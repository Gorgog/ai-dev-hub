# Оркестр без споров: организация автоматизированной ИИ-разработки на Claude Code

> Сводка исследования от 27.08.2026: 8 параллельных агентов, ~200 источников (доки Anthropic, arXiv, Reddit/HN, блоги практиков).
> Онлайн-версия: https://claude.ai/code/artifact/44162453-d950-417e-b50c-f3c02bf55f59

---

## 1. Фактчек: дают ли «спорящие ИИ» лучший результат?

Проверено по 10+ научным работам 2023–2026. Уверенность вывода: **высокая**.

| Вердикт | Подход | Суть |
|---|---|---|
| ❌ Миф | Свободные дебаты агентов до консенсуса | При равном бюджете токенов не обгоняют «сгенерировать N и проголосовать» (Debate or Vote, Stop Overvaluing MAD). Точность может *падать* от раунда к раунду — агенты поддакивают и меняют правильный ответ на неправильный (Talk Isn't Always Cheap). Цена: 16–25× токенов почти впустую. |
| ✅ Работает | Исполнение кода как арбитр | Тесты и запуск — самый воспроизводимый механизм прироста: AlphaCodium (19%→44% CodeContests), AgentCoder (96.3% HumanEval при *меньшем* расходе токенов), CodeT (+18.8 п.п.). Ключ: тесты пишет агент, который **не видел** реализацию. |
| ✅ Работает | Асимметричная критика | Один ревьюер с чистым контекстом (видит только дифф и критерии), которому велено **опровергать**: ~2 бага/PR, 58% серьёзных (Cognition). CriticGPT: критик находит больше багов, чем платные ревьюеры-люди. Спор решают тесты/человек, а не консенсус агентов. |
| ⚠️ Узкая ниша | Структурированные дебаты гетерогенных моделей | Только для архитектурных решений без «исполняемого оракула»: разные вендоры (Claude + GPT), спор вокруг конкретных улик, мало раундов, независимый судья. Единицы процентов прироста за ~10–25× токенов. |

**Правило:** лишние вычисления тратить на **проверку** (тесты, запуск, чистое ревью), а не на **разговоры** (дебаты, консенсус, ролевые игры).

Источники: [Du et al.](https://arxiv.org/abs/2305.14325) · [Stop Overvaluing MAD](https://arxiv.org/abs/2502.08788) · [Debate or Vote](https://arxiv.org/abs/2508.17536) · [Talk Isn't Always Cheap](https://arxiv.org/pdf/2509.05396) · [Why Multi-Agent Systems Fail (MAST)](https://arxiv.org/abs/2503.13657) · [AgentCoder](https://arxiv.org/abs/2312.13010) · [CriticGPT](https://cdn.openai.com/llm-critics-help-catch-llm-bugs-paper.pdf) · [Cognition: What's Actually Working](https://cognition.com/blog/multi-agents-working)

## 2. Память: чтобы ИИ помнил всё между сессиями

Главный инсайт: **сложность не в хранении, а в извлечении**. Дисциплинированный markdown в git обгоняет «стартапы памяти».

Сессия и модель сами ничему не учатся — «обучение» живёт в файлах, которые одна сессия пишет, а следующие читают.

### Три слоя (~95% ценности)

1. **Нативная база (уже встроено, бесплатно).**
   - `CLAUDE.md` в корне проекта — **< 200 строк**, дальше правила игнорируются. Ритуал Бориса Черни (создатель Claude Code): каждая ошибка ИИ → правило в CLAUDE.md.
   - `.claude/rules/*.md` — тематические правила с привязкой к путям (`paths:` в frontmatter).
   - Автопамять Claude Code (`~/.claude/projects/<проект>/memory/`) — включена по умолчанию, ревизовать через `/memory`.
   - У сабагентов может быть своя память: `memory: project` во frontmatter — ревьюер накапливает знание типичных багов проекта.
2. **Git как долгая память.**
   - `docs/decisions/` — журнал решений («выбрали X, отвергли Y, потому что…») — не пересматривать решённое.
   - Скилл «wind-down»: итог сессии → `docs/sessions/ГГГГ-ММ-ДД.md` (контекст, решения, открытые вопросы, следующие шаги). Новая сессия начинает с чтения последнего.
   - Структурированные коммиты — `git log` как база знаний.
   - Для длинных бэклогов: [Beads](https://github.com/gastownhall/beads) — git-трекер задач для агентов.
3. **Автоматический «тотальный отзыв» — только если реально нужен.**
   - [claude-mem](https://github.com/thedotmack/claude-mem) (~92k звёзд, локальный SQLite) — поиск «что мы решили про биллинг три недели назад».
   - Облачные (mem0 и т.п.) — скепсис: независимый замер 49% против заявленных 91.6%, код уезжает в чужое облако.

**Compound engineering** (Every): после каждой задачи — минута «кодификации»: уроки → CLAUDE.md / скилл / журнал решений. Каждая фича делает следующую дешевле.

## 3. Оркестрация: какой паттерн для какой работы

Anthropic и Cognition независимо сошлись: **один главный цикл держит состояние; сабагенты — узкие, без записи в код, возвращают выжимку**. Сабагент живёт в изолированном контексте: перелопатил 50 файлов — вернул два абзаца. Контекст оркестратора не засоряется.

| Задача | Паттерн |
|---|---|
| Новая фича | Один сильный «писатель» + цикл план→код→проверка. Тесты — независимый агент. Сабагенты только на разведку (read-only). |
| Ревью / поиск багов | Лучший кейс мульти-агентов: ревьюер с чистым изолированным контекстом, настроен опровергать. |
| Крупный рефакторинг | Оркестратор-воркеры только по независимым швам: 3–5 воркеров в git worktree, слияние в один поток. Сквозные правки — один агент. |
| Исследование / аудит | Параллельный веер read-only агентов с разными углами поиска, синтез в конце (+90% у Anthropic, но ~15× токенов). |

Экономика: разведка — дешёвые модели (Haiku/Sonnet), интеллект (оркестратор, сложная реализация) — Opus/Fable.

## 4. Конвейер этапов (spec-driven)

Источник истины — версионируемая спека, не переписка в чате.

1. **Идея → Спека.** «Проинтервьюируй меня по фиче X, потом запиши полную спеку в SPEC.md». Спека обязана включать требования авторизации/безопасности (дыры вайбкодинга живут в спеке) и финальный сценарий проверки. Тяжёлый вариант: [GitHub Spec Kit](https://github.com/github/spec-kit).
2. **Спека → План.** Свежая сессия, план-режим (Shift+Tab). Правишь план, не код. Черни: план-режим «легко 2–3×» на сложных задачах.
3. **План → Задачи.** Одна задача = один контекст + проверяемый итог.
4. **Реализация (TDD).** Падающий тест → **коммит теста** (иначе агент «подгонит» тест — коммит делает это видимым) → реализация до зелёного → рефакторинг → коммит. TDFlow: агентный TDD поднимал решаемость 12%→50%. Параллель — `claude --worktree`.
5. **Верификация.** Пирамида ниже.
6. **Отгрузка + Кодификация.** PR через git, CI гоняет те же проверки, уроки → в правила.

⚠️ **Автономные циклы («Ralph»)** — `while true; claude -p` — только для точно специфицированной работы, в контейнере, с тестами как воротами и лимитом итераций. На неоднозначной задаче ухудшает код с каждым проходом и жжёт $50–100 за ночь.

## 5. Сетап `.claude/` (макет)

Всё нативное, коммитится в git, одинаково работает локально/в облаке/CI. Тяжёлые фреймворки (Claude Flow, SuperClaude) — избыточны, Anthropic впитала их ценность в продукт.

```
репозиторий/
├── CLAUDE.md                  # <200 строк: стек, команды, жёсткие правила
├── docs/decisions/            # журнал решений
├── docs/sessions/             # итоги сессий (пишет скилл wind-down)
├── .github/workflows/claude.yml  # @claude в PR + авторевью
└── .claude/
    ├── settings.json          # хуки + разрешения
    ├── agents/
    │   ├── architect.md       # read-only, план-режим, сильная модель
    │   ├── implementer.md     # полные инструменты, memory: project
    │   ├── reviewer.md        # ТОЛЬКО Read/Grep/Glob — докладывает, не чинит
    │   └── tester.md          # Bash+Read: гоняет тесты, докладывает дословно
    ├── skills/
    │   ├── feature/           # /feature: архитектор→план→код→ревью→тесты
    │   ├── wind-down/         # итог сессии → docs/sessions/
    │   └── ship/              # коммит+PR только при зелёных воротах
    └── hooks/
```

**Хуки** (CLAUDE.md — совет, хук — закон):
- PostToolUse (Edit/Write): автоформат + тесты затронутого файла, ошибки → агенту в контекст.
- PreToolUse: блок `.env`, локфайлов, миграций, опасных команд.
- Stop-хук: агент не завершит ход, пока сборка/линт/тесты не зелёные.
- SessionStart (после компакции): заново вбросить критические правила.

## 6. Пирамида верификации (не читая каждую строку)

Зачем: ~45% ИИ-кода содержит уязвимости OWASP (Veracode, не меняется два года); половина выигрыша скорости съедается переделкой (Stanford, 100k разработчиков). **Проверка — узкое место, не генерация.**

| Слой | Что | Частота |
|---|---|---|
| L0 | Песочница/контейнер, worktree для рискованного; YOLO только в контейнере | всегда |
| L1 | Хуки: тайпчек + линт + Stop-ворота «до зелёного» | каждый эдит |
| L2 | Тесты, которые агент обязан пройти (замысел утверждаешь ты); property-based для инвариантов | каждая фича |
| L3 | Мутационное тестирование — ловит «лгущие тесты» (кейс: 100% покрытие, 61% реальной силы) | еженедельно / рисковые модули |
| L4 | Security-статанализ: Semgrep + security-review | каждый PR |
| L5 | Один малошумный ИИ-ревьюер PR, которого реально читаешь | каждый PR |
| L6 | Кросс-модельное второе мнение, **read-only**. Асимметрия ([arXiv 2607.21656](https://arxiv.org/html/2607.21656v1)): сильный ревьюит слабого (+18 п.п.); слабый ревьюер сильного автора *ухудшил* код (−8.6 п.п.) | рисковые изменения |
| L7 | E2E-доказательства: реальный сценарий в браузере (Playwright MCP), скриншоты/консоль/сеть | перед «готово» |
| L8 | Ты: форма диффа (дубли, крайние случаи), замысел тестов, всё про авторизацию/деньги/удаление данных — руками | выборочно |

## 7. Практики тяжёлых пользователей

**Делать:**
- Дать ИИ способ самопроверки — «стоит 2–3× качества» (№1 у всех).
- План до кода на всё нетривиальное; правь план, не результат.
- `/clear` между несвязанными задачами; контекст — самый дефицитный ресурс.
- Правило двух ошибок: две неудачные поправки → `/clear` и новый промпт с учётом выученного.
- Показывать образец («сделай как таблица users») вместо абзацев описаний.
- Вставлять сырые логи ошибок, не пересказывать.
- Параллель через worktree, но не шире способности проверить слияние.
- Автономность по риску: авто-принятие для периферии, надзор для ядра.

**Не делать:**
- Сессии-«свалки»; спираль поправок в деградировавшем контексте.
- Верить «готово» без доказательств — уверенно-неправильное дороже явно сломанного.
- CLAUDE.md на 400+ строк; отдавать ИИ архитектурные решения.
- Гигантские непросмотренные диффы; куча MCP «на всякий случай».
- Наводящие вопросы («правда же хорошо?») — получишь поддакивание.

## 8. Альтернативы: есть ли лучше Claude Code?

Как хаб оркестрации — **нет** (сабагенты, хуки, скиллы, workflows, worktrees, headless/CI; Opus 5 лидирует на Terminal-Bench 3.0: 42.7% vs 34.6% GPT-5.6). На насыщенных бенчмарках (SWE-bench ~96%) разницы между лидерами уже нет.

Дополнить:
- **Codex CLI (GPT)** — второе мнение из другого семейства: read-only аудит рисковых диффов.
- **Облачный PR-агент** — асинхронный разбор бэклога.
- **Cursor / Copilot** — скорость набора (у Claude Code нет автодополнения).
- **BYOK-запасной** (opencode, Kilo) — страховка от нестабильных лимитов подписки (главный реальный риск Claude Code).

Пропустить: Devin ($500/мес), swarm-фреймворки, облачные сервисы памяти.
