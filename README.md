# ai-dev-hub

**ИИ-разработчик, который с каждой задачей работает лучше.** Готовый набор правил, скиллов и агентов для
[Claude Code](https://claude.com/claude-code): ставится одним клоном, подходит для любого проекта.

## Зачем это

- **ИИ учится на ваших проектах.** В конце каждой сессии `/hub:wind-down` записывает, что сделано, какие решения
  приняты и где были ошибки. Поправили ИИ один раз — это становится правилом, и в следующей сессии он уже не
  ошибётся так же. Чем дольше работаете, тем меньше приходится объяснять.
- **Качество по умолчанию, вес — по задаче.** Крупное — сначала план, потом код; мелкое — короткий план и сразу
  работа. Логику и баги — сначала падающий тест, потом реализация. «Готово» —
  только с доказательствами: вывод тестов, скриншоты, логи. Ревью делает отдельный агент с чистым взглядом,
  который ищет ошибки, а не хвалит.
- **Несколько сессий параллельно.** Большую задачу `/hub:dispatch` режет на независимые части и ведёт их в
  отдельных сессиях одновременно. Каждая сессия работает в своей копии кода, тяжёлые проверки (дев-серверы,
  браузер, базы) идут по очереди. Решения по-прежнему принимаете вы.
- **Оценки, которые сверяются с фактом.** Перед задачей `/hub:estimate` ставит сложность 1–10, число MR и прогноз
  времени по похожим прошлым задачам. После задачи скрипт меряет по журналам сессий, сколько ушло на самом деле,
  а промах записывается с причиной. Чем больше закрытых задач, тем точнее следующие оценки.
- **Ваше остаётся у вас.** В git — только база. Проекты и их память живут на вашей машине и никуда не уходят.

Основано на исследовании `research/2026-08-27-ai-dev-orchestration.md`.

## Требования

| Что | Зачем |
|---|---|
| Windows 10/11, Windows PowerShell 5.1 | `sync-claude.ps1`, `headroom.ps1` (скрипты рассчитаны на Windows) |
| [Git for Windows](https://git-scm.com/download/win) ≥ 2.38 (Git Bash, `cygpath`) | worktree, `merge-tree --write-tree`, скрипты `*.sh` |
| [Node.js](https://nodejs.org/) ≥ 18 | хук-замок диспетчера и его скрипты (`*.cjs`), подсчёт факта в `/hub:estimate` |
| [Claude Code](https://claude.com/claude-code) | всё. Для `/hub:dispatch` — десктопное приложение: запуск и список сессий (`start_session`, `list_sessions`) есть только там |
| Скиллы `workplan` и `grilling` | нарезка на срезы в `/hub:dispatch` (любая реализация с `plan.md`, файлом на срез и `blocked-by`). Как они называются у тебя — в профиле проекта |

Без Node.js хаб работает, но очередь диспетчера держится только на правилах, без замка, а `/hub:estimate` ставит
прогнозы без замера факта. Без десктопного
приложения работают правила, `/hub:new-project` и `/hub:wind-down`, а `/hub:dispatch` — нет.

## Новый компьютер

1. `git clone https://github.com/Gorgog/ai-dev-hub.git <папка>` — путь любой, дальше `<хаб>`. Пути внутри
   правил и скиллов пишутся как `<хаб>`, скрипты находят себя сами.
2. Скопировать `CLAUDE.local.md.example` в `CLAUDE.local.md` и вписать своё имя и язык ответов.
3. Плагин: `claude plugin marketplace add <хаб>` и `claude plugin install hub@hub` — или
   `powershell -ExecutionPolicy Bypass -File <хаб>\sync-claude.ps1`, который делает то же через настройки:
   - в `~/.claude/settings.json` (с бэкапом) — маркетплейс `hub` из этой папки и включённый `hub@hub`. Плагин
     читается на месте: правки хаба видны со следующей сессии, обновлять ничего не нужно;
   - плагин даёт скиллы `/hub:*`, агентов `hub:reviewer`, `hub:explorer`, `hub:tester` и хуки: правила памяти
     при каждом вызове инструмента (новые правила начинают с режима `log` — подсказка и журнал, без блока;
     поднять до `ask`/`deny` — `modes` в `projects/<имя>/rules.json`), бриф проекта на старте сессии, проверку
     «готово к пушу» и замок диспетчера (только в `projects/*/worktrees/*`);
   - следы старой установки (junction-ссылки в `~/.claude/skills/`, копии агентов, хук-замок в настройках)
     убираются, копии — в бэкап;
   - git хаба получает свои хуки из `.githooks/`: pre-commit не пустит в публичный хаб строку с именем
     рабочего проекта, ключом задачи или студии. Список — в `.githooks/private-patterns`, по регэкспу на строку;
     он личный и в git не входит.
4. Проект — `/hub:new-project имя` в сессии Claude Code из корня хаба. Папка `projects/` создаётся локально.
5. Многосессионная работа в проекте — профиль `projects/<имя>/dispatch-profile.md` и правила замка
   `dispatch-rules.json` по образцам из `templates/project/` (`dispatch-rules.example.json`); `/hub:dispatch` поможет их заполнить.
   Пока `dispatch-rules.json` нет, хук-замок в проекте не действует.

## Как пользоваться

1. **Новый проект:** `/hub:new-project имя` из корня хаба.
2. **Рабочая сессия:** запускать Claude Code из `projects/<имя>/repo/`. CLAUDE.md хаба и проекта подхватятся
   сами: они лежат в родительских папках.
3. **Большая задача:** Claude спросит, вести её одной сессией или несколькими. Несколько сессий ведёт
   `/hub:dispatch` (диспетчер, параллельные срезы, очередь тяжёлых ресурсов).
4. **Оценка задачи:** `/hub:estimate <ключ>` (или «оцени задачу») — прогноз до работы, факт и промах после. При
   взятии задачи и в `/hub:dispatch` оценка ставится сама.
5. **Задача от начала до пуша:** `/hub:fast-lane` — по оценке выбирает дорожку S/M/L (сколько плана, ревью, браузера,
   мутантов); по ходу — `/hub:checks` (формат, типы, связанные тесты только по своим файлам, сводка в 10 строк;
   команды — `projects/<имя>/checks.json` по образцу `templates/project/checks.example.json`); в конце — `/hub:ship`:
   ревью, полный прогон, доказательства, доклад с текстом MR и один вопрос о пуше. Баг без ясной причины —
   `/hub:debug`.
6. **Конец сессии:** `/hub:wind-down` — итог уходит в локальную память проекта, открытая оценка закрывается фактом.
7. **После правки хаба** (скилл, агент, хук): видно со следующей сессии или после `/reload-plugins` — плагин
   читается из папки хаба на месте. `sync-claude.ps1` нужен только при установке.
8. **Правила памяти механизмом:** повторившийся урок из `errors.md` — правило в `projects/<имя>/rules.json`
   (`tools`, `commands`/`input` — регэкспы, `text`). Журнал срабатываний — `memory/rules-guard.log`; правило без
   ложных срабатываний переводится в `deny` через `modes`.

## Память проекта

Память — то, за счёт чего ИИ с каждой сессией работает лучше. Она живёт в `projects/<имя>/` только на этой машине
и в git хаба не попадает. Заготовки всех файлов создаёт `/hub:new-project` из `templates/project/`.

| Файл | Что туда | Кто и когда пишет | Кто читает |
|---|---|---|---|
| `CLAUDE.md` | короткие правила проекта: стек, команды, запреты, ссылки на рецепты. ≤ 200 строк и ≤ 20 КБ | после значимой задачи; урок, общий для проекта | каждая сессия — подгружается сама |
| `memory/errors.md` | правила из ошибок: «НЕ делай X. Вместо этого Y. (дата, откуда)». Архив: только дописывать, дубль — уточнить существующее | сразу после поправки пользователя или найденного ляпа | поиском по ключам из индекса |
| `memory/errors-index.md` | выжимка `errors.md` по темам: ≤ 150 строк, правило одной строкой, ключи для поиска | вместе с общим правилом в `errors.md` | хук на старте сессии — брифом: целиком или (`brief.json`, образец `templates/project/brief.example.json`) общие разделы целиком, прочие — строкой «по касанию» |
| `rules.json` | повторившиеся уроки как правила хука rules-guard: регэксп вызова, текст, режим (`log` → `ask`/`deny`) | на втором повторе урока (`/hub:wind-down`) | при каждом вызове инструмента, журнал — `memory/rules-guard.log` |
| `memory/recipes.md` | длинные рецепты и обоснования: команды по шагам, обходы, «почему так» | когда правило в CLAUDE.md требует подробностей | по ссылке «→ recipes: <раздел>» |
| `memory/decisions.md` | решения: что выбрали, что отвергли, почему, где (коммит, файл) | когда пользователь решил развилку | при работе в той же области |
| `memory/sessions/ГГГГ-ММ-ДД-<тема>.md` | итог сессии: контекст, сделано (с доказательствами), решения, грабли, дальше | `/hub:wind-down` в конце каждой сессии | следующая сессия — последнюю заметку |
| `memory/estimates.md` | журнал оценок: прогноз (сложность 1–10, MR, признаки, время) до работы, факт по журналам сессий, промах и причина; сверху поправки и якоря шкалы | `/hub:estimate` при триаже и при «готово к пушу», `/hub:wind-down` закрывает открытую оценку | `/hub:estimate` — аналоги и поправки для следующей оценки |
| `memory/branches.md` | статусы веток и MR (если проект их ведёт); каждая запись верна на свою дату | после пуша, MR, мержа | перед действием с веткой — со сверкой по git |
| `dispatch-profile.md`, `dispatch-rules.json`, `memory/dispatch.md` | многосессионная работа: профиль, правила замка, доска диспетчера | диспетчер (`/hub:dispatch`) | диспетчер, хук-замок |

Правила, которые держат память полезной:
- **Факт — с доказательством.** В память идёт то, что проверено: вывод команды, коммит, ответ пользователя.
- **Одно правило — одно место.** В CLAUDE.md — правило, в `recipes.md` — подробности, в `errors.md` — история
  ошибки. Не копировать между файлами, а ссылаться.
- **Устаревшее не стирать молча.** Отменённое решение помечается `superseded: «…» (дата) — причина`.
- **Лимиты соблюдать.** CLAUDE.md переполнился — длинное в `recipes.md`. Индекс переполнился — слить близкие строки.
- **Под диспетчером** сессия задачи пишет только свою заметку и дописывает в конец общих файлов. CLAUDE.md проекта
  правит диспетчер по разделам «Предлагаю в CLAUDE.md» из заметок сессий.

## Оценка задач

Оценка «на глаз» ошибается в разы, а своих часов у ИИ нет. Поэтому `/hub:estimate` прогнозирует по аналогам и
меряет факт скриптом.

1. **Прогноз до работы.** Сложность 1–10 по якорям шкалы (реальные задачи с фактом), один MR или N срезов,
   признаки (бэк, фронт, миграция, новые ручки, DnD, развилки) и время `мин–макс`. Опора — 2–3 похожие закрытые
   задачи из журнала. Строка пишется в `memory/estimates.md` до начала и потом не правится. Новые вводные
   добавляются отдельной строкой «пересмотр».
2. **Факт после работы.** В ответах ставятся метки `⏱ EST-START <ключ>` и `⏱ EST-END <ключ>`.
   `plugin/skills/estimate/scripts/session-time.cjs` читает журналы сессий Claude Code (`~/.claude/projects/`)
   и делит время между метками на три части:
   - **активно** — работа ИИ, тесты, агенты;
   - **ожидание** — время, пока пользователь отвечал (в том числе на вопрос с вариантами и одобрение плана), не
     больше 20 мин на ответ;
   - **пауза** — 20 мин и больше без ответа (неотвеченный запрос разрешения, ночь) и всё, что сверх 20 мин
     ждало ответа: пользователь отходил.

   В оценку идёт только активное время. Несколько заходов по одному ключу (ревью, ребейз) складываются; копия
   истории в ответвлённой сессии не считается дважды.
3. **Промах — с причиной:** объём, развилки, окружение, ревью, доказательства, чужое (CI, деплой) или темп.
4. **Обучение.** Каждые 10 закрытых задач `/hub:estimate review` считает медиану «факт ÷ прогноз» по сложности и
   признакам, записывает поправки и обновляет якоря. Следующая оценка их читает. Пока закрытых задач меньше
   10–15, опора — аналоги, а не поправки.

**На другой машине.** Скилл, скрипт и правила приходят клоном хаба. Журнал оценок и журналы сессий — локальные:
опыт начнётся с нуля, если не перенести `projects/<имя>/memory/estimates.md` вместе с памятью проекта (в git
хаба его не класть). Скрипт меряет только сессии своей машины.

## Агенты

- `explorer` — разведка по коду, read-only, бережёт контекст основной сессии.
- `reviewer` — ревью с чистым контекстом, настроен опровергать; только докладывает.
- `tester` — гоняет проверки и пишет тесты по спеке, не глядя на реализацию.

## Принципы (из исследования)

- Один «писатель» кода и независимая проверка; никаких «спорящих ИИ».
- Тесты — арбитр: падающий тест → коммит → реализация до зелёного (для логики и багов).
- «Готово» = доказательства, не утверждения.
- Уроки каждой задачи кодифицируются в правила — проект учится.
