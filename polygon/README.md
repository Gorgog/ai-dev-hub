# Полигон хаба

Сценарии из реальных провалов хаба и прогон, который мерит, как с ними справляется версия хаба. Правку хаба
проверяют как код: прогон на ветке сравнивают с прогоном на `main` или на базовой линии v1 (`ef519e3`).

## Запуск

```bash
# хук-уровень: без модели, ~1 с, $0 — рабочее дерево хаба
node polygon/run.cjs --level hook

# та же проверка на ревизии из git (git archive во временную папку, без checkout)
node polygon/run.cjs --level hook --ref ef519e3 --out ~/hub-data/polygon/v1-ef519e3.json
node polygon/run.cjs --level hook --out ~/hub-data/polygon/branch.json
node polygon/run.cjs compare ~/hub-data/polygon/v1-ef519e3.json ~/hub-data/polygon/branch.json   # код 1, если что-то хуже

# модельный уровень: каждый прогон — настоящий `claude -p`, тратит лимит; тяжёлое замка — только по разрешению
bash plugin/skills/dispatch/scripts/hub-run.sh <wt>-evals -MemoryMax 3G -- \
  node polygon/run.cjs --level model --repeats 3 -j 2 --only '^M0[12]'
node polygon/run.cjs regrade <results.json>   # пересчитать проверки по сохранённым транскриптам, без модели
```

Флаги: `--only <regex>` по id сценария, `--quiet` — только итоги, `--strict` — код 1 при красной проверке ворот
(без него красные проверки — данные, а не сбой), `--work <dir>` — где строить фикстуры (по умолчанию
`$TMPDIR/hub-polygon`), `--out` — файл результата (по умолчанию `$HUB_DATA/polygon/results/`).

## Итог прогона

```
$ node polygon/run.cjs --level hook --ref ef519e3 --quiet
ворота: 33/57 · ловит 23/33 · не шумит 10/24
прототип H01–H04: 24/45
контракты (вне ворот): 3/14 — H06, H09, H10, H12, H13, I01
  lock             ловит 7/13  не шумит 2/7
```

Базовая линия v1 из `acceptance.md` §1 (24/45: ловит 16/24, не шумит 8/21) — строка «прототип H01–H04»: те же
проверки, что у прототипа. Строки корпуса, добавленные позже (`proto: false`), и сценарии H05+ входят в ворота, но
не в эту строку; `--only '^H0[1-4]$'` даёт ворота прототипа отдельно.

- **Вид проверки** (`kind`): `catch` — нужен блок или флаг («ловит»), `quiet` — не нужен («не шумит»),
  `never` — «никогда» (пуш, `.env`, выдуманный sha, применённая миграция), `task` — сама задача.
- **Механизм** (`mech`) — у сценария, его можно переопределить у проверки. `compare` сравнивает «ловит» и «не
  шумит» раздельно и по механизмам, не средним: правило сравнения версий — `acceptance.md` §1.
- **Вне ворот:** наблюдение (`observe`: ходы, цена, был ли ревьюер), контракт (`contract` у сценария —
  механизма ещё нет, сценарий красный до своего среза), реальный корпус, пропуск (`skip`: нет systemd у H08).
  Контракт, который позеленел и снова покраснел, `compare` считает регрессией.
- Многократный прогон засчитывает проверку, только если она прошла во всех повторах (pass^k).

## Как устроено

- `lib/hub.cjs` — версия хаба (`CLAUDE.md`, `plugin/`, `templates/`) из ref или рабочего дерева + мини-хаб
  фикстуры: синтетический `CLAUDE.local.md`, `projects/demo/` (память из шаблона версии), репозиторий с git.
- `lib/hooks.cjs` — хуки как чёрный ящик: `hooks.json` → команда, JSON события на stdin (контракт Claude Code).
  Внутренности хуков не импортируются — сценарии переживают переписывание хуков.
- `lib/claude.cjs` — `claude -p --plugin-dir <версия>/plugin --setting-sources project,local --strict-mcp-config
  --no-session-persistence`; установленный плагин, другие плагины и MCP отрезаны. `AI_DEV_HUB` указывает на
  мини-хаб.
- `lib/shell.cjs` — свой разбор shell (`cd` вне подоболочки), независимый от регэкспов хаба; общий с аналитикой и
  замком следующих срезов. `lib/grade.cjs` — git фикстуры и вызовы из транскрипта. `lib/inject.cjs` — проверки
  инъекций. `lib/report.cjs` — итоги и `compare`. `lib/corpus.cjs` — реальные корпуса.
- `fixtures/dispatch-rules.json` — синтетика правил замка по `templates/project/dispatch-rules.example.json`.

## Данные

Хаб публичный: в git — код, синтетика и обезличенные случаи (ключи задач — `case-NN`, проекты — «проект A»
многосессионный, «проект B» малый). Реальное — только в `$HUB_DATA/polygon/` (по умолчанию `~/hub-data`):

- `case-map.json` — `case-NN` → ключ задачи;
- `corpus/<сценарий>.json` — реальные строки корпуса (сейчас H02, H03; у H02 рядом `H02-rules.json` — правила
  замка живого проекта). Случай — объект с полями строки `CORPUS` сценария; его проверка — `real:<id>`, своя
  строка итога. Нет каталога — прогон пишет «реальные корпуса пропущены»;
- `results/` — результаты прогонов.

## Pre-commit

`.githooks/pre-commit.d/20-polygon.sh`: если коммит трогает `CLAUDE.md`, `plugin/`, `templates/` или `polygon/`,
хук-уровень гоняется на `main` (`POLYGON_BASE_REF`) и на рабочем дереве, `compare` с регрессией не пускает
коммит. Только детерминированные сценарии; модельные — тяжёлое, в pre-commit их нет.

## Новый сценарий

Файл `scenarios/<id>-<суть>.cjs` (или массив вариантов): `level: 'hook'` → `run()` возвращает проверки;
`level: 'model'` → `setup()` строит фикстуру и промпт, `grade()` проверяет итог. У проверки — `id`, `pass`,
`detail`, `source` (откуда провал: запись `errors.md`, строка журнала, пункт аудита), `kind`. Грейдер модельного
сценария сначала проверяется на синтетическом транскрипте (`scenarios.test.cjs`), потом на 1 повторе модели с
чтением транскрипта: красная проверка — гипотеза, пока транскрипт её не подтвердил.
