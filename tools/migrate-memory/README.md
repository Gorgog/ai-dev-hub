# migrate-memory — память v1 → v2 по файлу соответствия

Записи старой памяти проекта (`errors.md`, `errors-index.md`, `recipes.md`, `decisions.md`) становятся уроками
`memory/lessons/<id>.md` и решениями `memory/decisions/<id>.md` формата v2 (срез 14, `plugin/lib/memory/format.cjs`).
Что куда — решает агент один раз в файле соответствия; скрипт только применяет его, детерминированно: два прогона на
одном снимке дают одно и то же побайтно.

```
python3 tools/migrate-memory/migrate.py --snapshot <снимок> --list [--project <имя>]        # записи — из них пишут файл
python3 tools/migrate-memory/migrate.py --snapshot <снимок> --map <map.json> --out <папка> [--check-twice]
node tools/migrate-memory/why.cjs --out <папка> --set <why.json>                        # «почему так решили»
node tools/migrate-memory/triggers.cjs --out <папка> --calls <calls.db> [--cases <cases.json>]   # шум и попадания when
```

`why.cjs` — тест 7 приёмки памяти без модели: вопрос → поиск библиотеки памяти (путь `recall find`) по копии памяти
проекта; верно, если ожидаемое решение в топ-3; порог 80 %, набор 15–20 вопросов с эталонными ответами.
`triggers.cjs` — проверка `when` до хуков 21: подачи раз на (сессия, агент, эпоха, урок) по `calls.db`, на 20 вызовов,
медиана уроков на сессию, шумные уроки; попадания на случаях replay (`cases.json` прототипа). В `calls.db` нет
`body`/`out`: уроки на этих полях названы «не измерено», шум дан нижней границей (поле не совпадает) и верхней
(совпадает). Настоящий тест 6 — replay через модуль подачи среза 21.

`--out` заменяется целиком: это пустая или новая папка либо прежний прогон (только `anchor.json`, `addresses.json`,
`projects/`); папку с чем-то другим, предка снимка или файла соответствия и папку внутри снимка скрипт не трогает (код 1).

Снимок — папка с `projects/<имя>/memory/` (`~/hub-data/hub` из `tools/hub-data/snapshot.py`). Вывод — во временную
папку, живая память не трогается. Реальные снимки, файлы соответствия и прогоны — только в `~/hub-data/migration/`;
в git — код и синтетический пример `example/`.

## Записи

`records.py`: в `errors.md`, `errors-index.md`, `recipes.md` запись — пункт списка (`- ` с нулевой колонки) с
продолжениями с отступом; любая другая строка текста (абзац, продолжение без отступа) — своя запись, чтобы текст не
пропал молча. В `decisions.md` запись — раздел `## …` до следующего `## ` или `# ` (`### ` внутри). Заголовки и
HTML-комментарии — не записи. Адрес записи — `ref` = `<файл>#<sha12>` (sha256 текста; совпавший текст в том же файле —
`.2`, `.3`…). Правка текста записи меняет ref: файл соответствия пишется по свежему снимку и с ним остаётся.

## Файл соответствия

```json
{"version": 1, "projects": {"<имя>": {
  "lessons":   [{"id": "cd-in-subshell", "kind": "rule", "status": "active", "created": "2026-09-20",
                 "when": [{"tool": "^Bash$", "cmd": "(^|&&|;)\\s*cd\\s"}], "keys": ["cd"], "supersedes": [],
                 "from": ["errors.md#4228d715ff97", {"ref": "errors.md#…", "part": "cd"}],
                 "text": ["первая строка ≤ 160 знаков — её подают", "подробности: строки 2–5 любой длины"]}],
  "decisions": [{"id": "…", "created": "…", "keys": […], "from": […], "text": […]}],
  "archive":   [{"ref": "errors.md#…", "part": "…", "reason": "остаток Windows: …"}]}}}
```

- Каждая запись каждого файла проекта получает адрес: урок или решение `from` неё, или архив с причиной. Сирот нет.
- Несколько записей в `from` — слияние. Запись с двумя правилами разбивается: каждое её упоминание называет свою
  `part`; одна часть — ошибка (второе правило ушло в никуда).
- Урок: `kind` — `rule` | `once` (класс «одного раза», в отставку не уходит) | `knowledge`; `status` — `active`
  (по умолчанию) | `core`; `when` — блоки полей `tool`/`cmd`/`path`/`body`/`out` с сырыми регэкспами (флаг i), `[]` —
  только поиск. Решение — `kind: decision`, `when: []`. `source` всегда «модель (миграция)».
- Текст — 2–5 строк, первая ≤ 160 знаков; без URL и команд пуша/отправки/удаления (валидатор 14 отказывает).
- Ключи — без запятых и квадратных скобок по краям: файл пишет их списком `[a, b]`.

## Вывод и якорь

`<out>/projects/<имя>/memory/{lessons,decisions}/<id>.md` — файлы пишет и проверяет библиотека памяти
(`render.cjs` → `formatLesson` + `validateLesson`, затем чтение обратно: поле, которое не пережило запись, — отказ).
`<out>/addresses.json` — запись → куда ушла (строка, вид, урок/решение/архив, часть, причина). `<out>/anchor.json` —
sha256 каждого исходного файла и файла соответствия, число записей, отображённых, сирот, разбитых, слияний.
Любая проблема — код 1, список проблем, ничего не записано, прежний `--out` цел. `--check-twice` — весь прогон дважды
от входов, сверка побайтно, остаётся одно дерево.
