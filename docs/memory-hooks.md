# Хуки хаба: память v2 в хуках

Срез 21. Урок из памяти проекта приходит в тот момент, когда его признак виден в вызове, — один раз на эпоху агента,
через подачу ([delivery.md](delivery.md)). Запись урока проверяется сразу, Bash в уроки не пишет, история памяти
коммитится, порча памяти называется на старте. Формат памяти и библиотека — срез 14 (`plugin/lib/memory/`).

## Где действует

Только в проекте хаба, у которого есть `projects/<имя>/memory/lessons/` (память v2). В проекте со старой памятью и
вне хаба все модули возвращают `null`: ни подачи, ни отказа, ни событий, ни коммита.

Корень хаба и его папки вне `projects/` (`plugin/`, `research/`, `ideas/`) — проект `ai-dev-hub` (`lib/hub.cjs`
`findProject`), если такой проект есть (решение 05.11): в корне работает диспетчер этого проекта. Поэтому в
сессиях корня действуют канарейка, правила (`rules.json`), бриф (`errors-index.md`, заметки веток) и заглушки заметок
проекта `ai-dev-hub`; копией проекта (worktree, `repo/`) путь считается только внутри `projects/ai-dev-hub/` —
`worktreeOf`, бриф (`session-start.cjs`) и done-gate проверяют префикс, а не длину пути. `hubRoot()` читает настройки
из `CLAUDE_CONFIG_DIR`, если он задан.

Модули уроков (`memory-lessons`, `memory-repeat`) работают только при включённой подаче с памятью (`ctx.delivery`):
без её «один раз на эпоху» урок повторялся бы на каждом вызове.

## Модули (один обработчик `memory`, стадия `canary`)

| Механизм | Модуль | Что делает |
|---|---|---|
| `memory-lessons` | `posttool.d/21-memory-lessons.cjs` | `when` урока сработал на законченном вызове — урок сразу после него (PostToolUse) |
| `memory-repeat` | `pretool.d/51-memory-repeat.cjs` | урок уже подан в этой эпохе и его признак снова в вызове — отказ один раз с текстом урока (deny-once) |
| `memory-write-check` | `posttool.d/20-memory-write-check.cjs` | Write/Edit урока или решения — валидатор 14 сразу; ошибки — `block` с перечнем; `.triggers.json` пересобран |
| `memory-bash-write` | `pretool.d/50-memory-bash-write.cjs` | Bash пишет в `memory/lessons/` или `memory/decisions/` — `deny` с тем, как писать урок |
| `memory-commit` | `stop.d/30-memory-commit.cjs` | события уроков сессии → `memory/events/` проекта; коммит git памяти под `flock -n` |
| `memory-check` | `sessionstart.d/40-memory-check.cjs` | порча памяти (NUL, схема, рваные строки событий, битый индекс) — в бриф; ничего не блокирует |

Места подачи урока — решение 05.11 по P10: сразу после вызова, который сработал на признак, и перед повтором той же
ошибки в той же эпохе (один отказ; дальше вызов проходит, повтор считается подачей как `repeat`).

Признаки — поля вызова, как в прототипе памяти: `tool`, `cmd` (команда Bash), `path`, `body` (текст Write/Edit), `out`
(вывод Bash, только PostToolUse). Поле видно хуку первыми 4000 знаками (`out` — последними). Порядок при нескольких
уроках: ядро, затем более узкий признак (больше полей), затем id; подача берёт 3 на вызов.

## Горячий путь

`memory-hot.cjs` — то, что идёт на каждом PreToolUse/PostToolUse проекта с памятью v2: читает только
`memory/.triggers.json` и файл состояния сессии подачи, SQLite и `crypto` не трогает. Холодный процесс хука платит за
каждый загруженный байт и каждый скомпилированный регэксп, поэтому:

- модуль повтора сначала смотрит состояние сессии: нет поданных в эпохе уроков — библиотека не грузится;
- Bash-модуль и проверка записи грузят библиотеку только если в команде или пути есть `lessons`/`decisions`;
- у каждого регэкспа `when` — обязательный литерал (`literalOf`): сначала `includes`, регэксп компилируется только
  если литерал в поле есть; одинаковые источники (`^Bash$`) — один объект;
- предохранитель от катастрофического отката (ревью 05.11: `(\w|\d)+@` на sha, `(.|\s)*`, `\s*\s*\s*`): после
  10 000 откатов V8 перезапускает регэксп на линейном движке (`v8.setFlagsFromString` при загрузке). Линейный движок
  не берёт флаг `i`, поэтому триггеры работают «в нижнем регистре вручную»: буквы шаблона и поле — через
  `toLowerCase` (расходится с `i` только на σ/ς, µ/μ). Обратные ссылки и просмотр он тоже не берёт — такие источники
  судятся статически: вложенный повтор, повторяемая группа с альтернативой, три квантифицированных атома подряд — не
  берутся; SessionStart и проверка записи называют такой `when`;
- на 13 452 реальных вызовах × 312 триггерах совпадения с прежним `new RegExp(src, 'i')` одинаковы, кроме одного
  намеренно отключённого триггера (вложенный повтор с просмотром).

## Проверка записи и Bash

Запись `memory/lessons/<id>.md` или `memory/decisions/<id>.md` через Write/Edit/MultiEdit — `validateLesson` над
файлом как он есть на диске; ошибка — `block` (Claude видит причину и правит файл). Годный урок сразу попадает в
`.triggers.json`.

Bash, который пишет в эти папки или стирает их, — `deny`: перенаправление (с подстановкой переменных, заданных в
команде), `tee`/`touch`/`truncate`, `rm`/`rmdir`/`shred` (и папки, внутри которой память), `mv` (оба конца), `find
-delete`/`-exec`, цель `cp`/`install`/`ln`/`rsync` (и сама память, если в неё копируют папку `lessons`/`decisions`),
`sed -i`/`perl -i`/`awk -i inplace`, `patch`, `dd of=`, `curl -o`/`wget -O`, `tar -x -C`, git-команды, пишущие рабочее
дерево (`checkout`, `restore`, `reset`, …) с путём памяти или внутри её git, код интерпретатора (`-e`/`-c` или heredoc):
путь — первый аргумент вызова записи (литерал, переменная, `path.join`), копия из памяти наружу — чтение. Глоб в
первом сегменте под памятью сверяется с `lessons`/`decisions`. Не ловится: `… | xargs rm` (путь приходит из потока). Причина
говорит, как писать урок (Write/Edit), что регэксп `when` проверяет хук при записи, а не `node -e` (привычка из M11),
и что статусы и проверка — скилл `recall`. Чтение памяти, копия из неё, дозапись в старый `errors.md` — проходят.
Замер на `calls.db`: 0 запретов на 56 462 реальных Bash-вызовах; контроль (дозапись в `errors.md` как в урок) —
98 запретов, детектор умеет срабатывать.

## Журнал: куда пишется `shown`

В оба места, но подача пишет только в свой журнал (`<data>/events/`): только она знает, показан ли урок после
лимитов и «уже показан». Счётчики урока (отставка, `recall why`) живут в `memory/events/` проекта, поэтому Stop
переносит туда строки своей сессии с `lesson` (`shown`, `deny`, `repeat`, `prevented`, `expired`) — один раз, строка
узнаётся по (`at`, `kind`, `lesson`, `tool_use_id`, `agent_id`). Читается журнал текущего месяца (в первые два дня — и
прошлого), строки отбираются подстрокой `session_id` до разбора.

## Коммит памяти

`flock -n <memory>/.git/hub-memory.lock` → `git add -A -- lessons decisions events`, коммит только при изменении
(автор — `hub memory hook`, без хуков git и подписи). Замок занят — пропуск до следующего Stop (P14). Нет
`memory/.git` — ничего: git памяти заводит шаблон или миграция, не хук. Ошибка — строка `error` в `hooks.jsonl`.
