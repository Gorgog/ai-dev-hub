# Хуки хаба: хребет

Хребет — один процесс node на событие, поведение — модули-файлы, всё, что идёт в контекст Claude, — через одну
точку подачи. Новый механизм — новый файл модуля и запись реестра; `hooks.json` и раннер после среза 08 не правит
никто.

## Как устроено

```
hooks.json ─► node hooks/run.cjs <Событие>      (событие JSON на stdin)
                 ├─ выключатель: HUB_OFF=1 или файл <хаб>/.hub-off → выход, ни один модуль не грузится
                 ├─ hooks/<событие>.d/ пуст → выход до чтения stdin
                 ├─ SessionStart: проверка здоровья (lib/health.cjs)
                 ├─ модули по имени файла: 10-…, 20-… — стадия и политика отказа из plugin/mechanisms/<id>.json
                 └─ решение + подача (lib/deliver.cjs) → stdout / код 2, как ждёт Claude Code
```

| Событие | Каталог | Матчер | Что умеет вернуть |
|---|---|---|---|
| PreToolUse | `pretool.d/` | `Bash\|Edit\|Write\|MultiEdit\|mcp__Claude_Browser__.*\|mcp__claude-in-chrome__.*` | `block` (код 2, причина в stderr), `deny`/`ask` (JSON), подача — `additionalContext` |
| PostToolUse | `posttool.d/` | `Bash\|Edit\|Write\|MultiEdit\|NotebookEdit` | `block` (причина Claude), подача — `additionalContext` |
| PostToolUseFailure | `posttoolfailure.d/` | тот же | подача — `additionalContext` (по тексту ошибки инструмента); `block` раннер отдаёт как у PostToolUse, но для упавшего инструмента Claude Code его действие не проверено |
| Stop | `stop.d/` | — | `block` (Claude продолжает с причиной) |
| SessionStart | `sessionstart.d/` | `startup\|resume\|clear\|compact` | подача — простым текстом (как v1) |
| SessionEnd | `sessionend.d/` | — | ничего (только побочные действия) |
| SubagentStart | `subagentstart.d/` | — | подача — `additionalContext` субагенту |

`UserPromptSubmit` не заведён (решение 05.11). Проверено живым `claude -p --plugin-dir <worktree>/plugin` против
мок-API (Claude Code 2.1.317, 05.11): события доходят до раннера, `CLAUDE_PLUGIN_DATA` задан, при `HUB_OFF=1` ни один модуль не вызван, ошибок хуков 0.

## Контракт модуля

```js
// plugin/hooks/pretool.d/30-example.cjs
module.exports = {
  id: 'example',
  run(ev, ctx) {            // может быть async
    // ev — событие Claude Code как есть; ctx = { event, hub, project: {dir, name} | null, worktree, stage,
    //   version (короткий sha хуков), epoch (null до среза 12) }
    return null;            // или { decision: 'block' | 'deny' | 'ask', reason, items: [{ text, priority, key }] }
  },
};
```

- В stdout модуль не пишет: раннер перехватывает такой вывод, в Claude он не попадает, в журнал — строка `stdout`.
- `block`/`deny` обрывают цепочку; `ask` — нет (следующий `deny` сильнее). При решении подача не выводится.
- Подача (`lib/deliver.cjs`, заглушка до среза 12): приоритет `block > lesson > reminder > info`, один элемент на
  `key`, строки через перевод строки. Лимиты на вызов и на эпоху, ключ «уже показан» — срез 12.
- Результат вне контракта (не объект, неизвестный `decision`, `decision` без `reason`, `items` без `text`) —
  модуль сломан.
- Модуль не оставляет работу в фоне: перехват stdout снят, как только он вернул результат, а запоздалая запись
  испортит JSON следующего вывода. Зависший async-модуль доживает до таймаута хука (10 с), и Claude Code пропускает
  вызов — защита в этот раз открыта; модулю защиты — без сети и долгого I/O.

## Реестр и бюджет

`plugin/mechanisms/<id>.json`, по файлу на механизм:

| Поле | Что |
|---|---|
| `id` | = имя файла |
| `event`, `file` | событие и модуль (`pretool.d/10-lock.cjs`); каталог файла = каталог события |
| `handler` | логический обработчик (бюджет считает их) |
| `stage` | `off` / `canary` / `on` |
| `onError`, `failScope` | политика отказа: `open` / `closed` и где закрытый отказ действует: `any` / `project` / `worktree` |
| `state`, `reads` | файлы состояния, которые механизм ведёт (бюджет), и конфиги, которые читает |
| `polygon` | сценарии полигона (`H02`) — файл `polygon/scenarios/<id>-*.cjs` должен быть |
| `replaces`, `review` | что заменяет; дата пересмотра ГГГГ-ММ-ДД |

`.githooks/pre-commit.d/30-mechanisms.sh` проверяет индекс (то, что коммитится): модуль без записи, запись без
модуля или без сценария, неизвестные стадия/событие — отказ; логических обработчиков > 6 или видов состояния > 10 —
отказ с перечнем; каталог `*.d`, не принадлежащий событию (опечатка `pretools.d/`), и две записи на один модуль —
отказ; истёкший пересмотр — предупреждение. Вручную: `node plugin/hooks/lib/registry.cjs check .`.

Сейчас (08): обработчиков 4 из 6 (`lock`, `rules-guard`, `memory-brief`, `done-gate`), видов состояния 3 из 10.

## Стадии и канарейки

`off` — модуль не грузится; `on` — везде; `canary` — только в проектах, чей локальный файл
`projects/<имя>/canary.json` (вне git) перечисляет его: `{"mechanisms": ["<id>"]}`. Порядок выката нового модуля
(R2): проект хаба → проект B (малый) → `on`, по рабочему дню на ступень, глядя в журнал хуков. Откат — `off`, сразу.

## Политика отказа

Решение 05.11 (умолчания среза 08, приняты диспетчером): замок закрыт только в worktree проектов этого хаба;
rules-guard закрыт только внутри `projects/<имя>/` хаба, вне — открыт (плагин работает во всех сессиях
пользователя); бриф и done-gate открыты; ошибка внутри `guard.decide()` — открыто, как в v1.

Модуль сломан — бросил исключение (в том числе при загрузке) или нарушил контракт. Всегда — строка `error` в журнале.
Дальше по записи реестра:

- `onError: open` (подача, напоминания) — модуль пропущен, остальные идут.
- `onError: closed` (защита) внутри `failScope` (`worktree` и `project` — только этого хаба: `…/projects/*/worktrees/*`
  чужого репозитория вне области) — PreToolUse: `deny` с причиной (какой модуль, ошибка, как
  выключить хаб, где журнал), цепочка обрывается; Stop: `block`, но не при `stop_hook_active` (без петли). Вне
  `failScope` и на прочих событиях — как `open`.
- Нет записи или она битая — модуль идёт как `on` с закрытым отказом внутри проектов хаба (pre-commit такое не
  пропускает; проверка здоровья называет и модуль без записи, и каталог не события).
- Падение самого раннера — выход 0 (открыто): раннер проверяют тесты, полигон и pre-commit.

| Механизм | Модуль | Отказ | Где закрыт |
|---|---|---|---|
| lock | `pretool.d/10-lock.cjs` | closed | worktree проекта |
| rules-guard | `pretool.d/20-rules-guard.cjs` | closed | проект хаба |
| memory-brief | `sessionstart.d/10-memory-brief.cjs` | open | — |
| done-gate | `stop.d/10-done-gate.cjs` | open | — |

Восстановление: сломанный на `main` модуль закрытой защиты запрещает в своей области все вызовы Bash/Edit/Write,
включая сессию, которая пришла его чинить. Выход — из своего терминала, не из Claude: `touch <хаб>/.hub-off`, починить,
`rm <хаб>/.hub-off`. Причина отказа называет и файл-флаг, и журнал.

Ошибка внутри `guard.decide()` (битый `dispatch-rules.json`) — открыто, как в v1: это сломанный конфиг проекта, а не
модуль; его называет предполётная проверка брифа. `guard.cjs` — срез 15.

## Выключатель

- Файл `<хаб>/.hub-off` (или `.hub-off` рядом с `plugin/` копии для `--plugin-dir`) — действует сразу, в живых
  сессиях тоже: каждый вызов хука проверяет его первым. Убрать файл — хаб снова включён.
- `HUB_OFF=1` — в окружении сессии; живой сессии его не задать, это для запуска (`HUB_OFF=1 claude`) и для тестов.
- При выключенном хабе ни один модуль не грузится, stdin не читается, вывода нет, код 0.

## Проверка здоровья (SessionStart)

Раннер до модулей проверяет: node ≥ 22 и `node:sqlite`; корень хаба найден (`projects/` в `AI_DEV_HUB` или в
маркетплейсе `hub`); `hooks.json`, `base-rules.json`, записи реестра разбираются; хуки исполняются из чистой копии
на `main` — после пробы P17 хуки идут прямо из рабочего дерева основной копии, поэтому «другая ветка» или
незакоммиченные правки `plugin/` там — уже в бою. Здоров — молчит; нет — блок «Здоровье хаба (<sha>)» перед брифом.

## Версия и журнал

Метка версии — короткий sha копии, из которой идут хуки (`<plugin>/..`, читается из `.git` без процесса git; нет
git — `?`). Она в шапке брифа (`Бриф хаба: … · хаб <sha>`), в каждой строке журнала хребта и в строках
`memory/rules-guard.log` (поле `hub`).

Журнал хребта — `hooks.jsonl` в `$HUB_LOG_DIR`, иначе в `$CLAUDE_PLUGIN_DATA` (Claude Code задаёт его плагину:
`~/.claude/plugins/data/<плагин>/`), иначе `$TMPDIR/hub-hooks/`. Строки: `health` (каждый старт сессии: версия,
проблемы), `error` (сломанный модуль, применённая политика), `stdout` (модуль писал в stdout). День после выката R2 —
смотреть `error`:

```bash
jq -c 'select(.type=="error")' ~/.claude/plugins/data/*/hooks.jsonl | tail
```

## Цена

`node plugin/hooks/bench.cjs` — целый процесс на вызов, как платит Claude Code; синтетический хаб, 200 вызовов
вперемешку (node 26, 05.11):

| Что | p50 | p95 |
|---|---|---|
| PreToolUse v1 `ef519e3` | 24,2 мс | 27,8 мс |
| PreToolUse хребет | 31,2 мс | 37,0 мс |
| Пустое событие (PostToolUse без модулей) | 22,9 мс | 26,6 мс |
| `node -e ''` | 23,2 мс | 27,2 мс |

p95 PreToolUse: +9,2 мс к v1 (порог acceptance: ≤ +15 мс; разброс прогонов +7…+9). Пустое событие стоит запуска
node и `readdir` — столько стоит каждое событие без модулей (PostToolUse, PostToolUseFailure, SessionEnd,
SubagentStart после 08). Раннер выходит `process.exit()` сам, как v1 (естественное завершение node — ещё несколько мс
на вызов), но только после того, как его вывод записан: `exit()` сразу после `write` в пайп теряет всё сверх
ёмкости пайпа.

## Выкат (R2) и живые сессии

Claude Code читает `hooks.json` при старте сессии, а сами файлы хуков — при каждом вызове из рабочего дерева
основной копии (P17). Входы v1 (`pretool.cjs`, `session-start.cjs`, `stop.cjs`) оставлены и зовут раннер, поэтому
живая сессия после мержа работает по старому `hooks.json` на новых модулях: замок, rules-guard, done-gate и бриф при
компакции — те же. Новые события (PostToolUse, PostToolUseFailure, SessionEnd, SubagentStart) появятся у неё только
после перезапуска.

Сценарий (песочница `probes/platform`, мок-API, 05.11; CLI 2.1.317 и Desktop 2.1.309): плагин из `main` поставлен из
маркетплейса-каталога, живая сессия делает 3 вызова и ждёт мока, в это время каталог получает `plugin/` ветки и
коммит (мерж), после — 20 вызовов. Итог на обоих движках: 0 ошибок хуков, все 20 PreToolUse прошли через хребет,
напоминание rules-guard на `git add -A` пришло. Контроль — тот же мерж без входов v1: 21 ошибка хука
(`Cannot find module …/pretool.cjs`) — без входов мерж при живых сессиях ломал бы им хуки.

Мерж при открытых сессиях безопасен, пока: входы v1 лежат на месте; мерж — одним `git merge` в основной копии без
ручных правок `plugin/`; поведение модулей = v1 (полигон, «хуже: 0»). Остаётся окно самой записи файлов (git пишет их
не атомарно, миллисекунды): вызов, попавший между новым `pretool.cjs` и ещё не записанным `run.cjs`, падает с кодом 1
— Claude Code считает это несблокирующей ошибкой и пропускает вызов без замка. Удалять входы v1 — когда не останется
сессий, начатых до мержа 08 (следующий R2-срез, при нуле живых сессий).
