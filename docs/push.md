# Пуш: push-slice и голый git push

Срез 18. Пуш в проектах хаба — только скриптом с воротами; голый `git push` запрещает хук. Шаги диспетчера —
`plugin/skills/dispatch/push.md`, одиночной сессии — скилл `ship`, сессии задачи — бриф (`dispatch/brief.md`).

## Как устроено

```
сессия: checks --full ─► ревью ─► доказательства        три точки паузы, 1–7 пунктов на точку
            │               │            │                «объект → наблюдение → подтверждение-след»
            └───────────────┴────────────┴─► memory/<ветка>/ready.json ─► push-slice verify (только расхождения)
диспетчер / ship: push-slice push … --dry-run ─► вопрос пользователю ─► push-slice push …
                 квитанция · вершина и чистое дерево · parallel-check · история · риск ─► git push <sha>:refs/heads/<ветка>
хук bare-push: git push в корне хаба, repo/ проекта, worktree ─► deny с путём через push-slice
```

| Ворота | Отказ |
|---|---|
| квитанция | нет квитанции пушимой ветки (чужая не в счёт; `main` после волны — `--integration`); нет файла; sha не вершина ветки; точки паузы нет или в ней > 7 пунктов; след не сходится (коммит не в ветке, файла нет или он изменился, лог прогона не на итоговом HEAD, скрин не PNG/JPEG, ревью «Блокирует: да») |
| ветка | вершина ушла после доклада; worktree ветки не чист |
| parallel-check | `--wave`: текстовый конфликт с веткой волны; `--solo`: конфликт с базой; ни того ни другого — отказ |
| история | диапазон — коммиты, которых нет ни в одной ветке remote; база опережает remote — «сначала пуш базы»; не fast-forward remote (после ребейза — `--lease <вершина>` по ответу пользователя); чужой автор без `--foreign-ok`; коммит не под квитанцией (мерж проходит, сквош — по patch-id); имя из `private-patterns` в коммите или его тексте — сквош |
| риск | по каждому коммиту диапазона (не дифф деревьев): CI, деплой, зависимости, сеть (вне доков и тестов), секреты — без `--risk-ok <категории>` |
| след checks | `output`: лог на итоговом HEAD без строк FAIL / `not ok` / `✖`; `last-full`: полный sha = HEAD, `code` 0, `clean` true |

Коды выхода: 0 — пройдено / запушено; 1 — ворота отказали; 2 — вызов; 3 — не смог прочитать (git, remote);
4 — квитанция говорит «Остановлено: аномалия» (законный исход доклада, пуша нет).

## Механизм bare-push

- Модуль `plugin/hooks/pretool.d/40-bare-push.cjs`, логика — `plugin/hooks/push.cjs`; запись реестра
  `plugin/mechanisms/bare-push.json`, обработчик `push` (7-й из 10), отказ закрытый внутри проектов хаба, полигон
  H34.
- Программы читает разбор shell замка (`dispatch/scripts/shell.cjs`): обёртки, `bash -c`, подоболочки. Где
  действует git — `-C <папка>` и буквальный `cd` перед ним; переменная там — папка сессии. Не известное до запуска
  (`eval "$X"`) — по тексту: `git`, его глобальные флаги, затем `push` (`git stash push` — не пуш). Подоболочка,
  `bash -c`, `cd -`, `popd`, `env -C` — в счёт идут папка сессии и все названные папки (сторона блока). Пуш — и
  `send-pack`, `subtree push`, алиас из `-c alias.x=push`; папка — и `--git-dir`, `--work-tree`, `GIT_DIR`. Алиасы из
  конфига git хук не видит.
- Тишина: `push-slice` (его git-процесс хук не видит), `git push --dry-run`/`-n`, упоминания в тексте, пуш вне
  хаба.
- Замер на `calls.db` (56 462 Bash-вызова, все как будто в `repo/` проекта; после правок ревью): deny 0,53 на 100,
  запретов не-пушей (против флага пуша аналитики) — 0, исключений — 0.

## Выкат и откат

R1 (скиллы, агенты, шаблон брифа) — мерж + sync. R2 (модуль) — после того как `push-slice` есть в `main`, по
стадиям: проект хаба → проект B → `on`. На стадии `canary` модуль работает только в `projects/<имя>/` (канарейку
раннер берёт из `projects/<имя>/canary.json`). В корне хаба модуль действует только со стадии `on` (project = null). Откат — `"stage": "off"` в записи
реестра (сразу) или revert + sync.
