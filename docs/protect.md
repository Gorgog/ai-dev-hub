# Защита механизмом (срез 13)

Частые и опасные ошибки останавливает хук, а не текст правила. Четыре механизма под одним логическим обработчиком
`protect` (бюджет: 5 обработчиков из 6): модули `plugin/hooks/pretool.d/30..33-*.cjs`, логика — `plugin/hooks/protect.cjs`,
записи — `plugin/mechanisms/<id>.json`, тесты — `plugin/hooks/protect.test.cjs`, полигон — H17–H21. Решение — `deny` с
причиной, которая говорит, что делать вместо; сломанный модуль закрыт внутри проектов хаба (`onError: closed`,
`failScope: project`). Bash читается разбором shell (кавычки, `$( )`, `$'…'`, heredoc, перенаправления, арифметика
`$(( ))`/`(( ))`, сравнения в `[[ ]]`, `cd` и `S=…; $S` в пределах команды, глобы `*`/`?` — по диску, скобки `[id]` — буквально), не подстрокой: текст в
сообщении коммита, в `echo` и в теле heredoc не срабатывает.

| Механизм | Запрещает | Пропускает |
|---|---|---|
| `protect-files` | правку существующего `.env`/`.env.*`, локфайла (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, …), миграции, уже лежащей в HEAD (папка `migration(s)/` или `db/migrate/` в пути от корня репозитория; `rm -r`/`mv` папки, под которой в HEAD есть миграции) — Edit/Write/MultiEdit/NotebookEdit и запись из Bash (`>`, `>>`, `tee`, `sed -i`, `perl -i`, `cp`/`mv`/`rm`, `git rm`) | чтение; `.env.example` и прочие образцы; новый `.env`; новую миграцию (нет в HEAD); документацию в папке миграций (`.md`, `.txt`); `git add` локфайла; `git rm --cached .env` |
| `inline-script` | скрипт `node -e "…"`, `python -c "…"`, `perl -e "…"` или heredoc без кавычек в интерпретатор/в файл кода, где shell сам перепишет тело: обратная кавычка, `\\`, `${…}`, который не параметр shell. В причине — путь для Write и готовая команда: та же команда, где тело заменено на `-e "$(cat <файл>)"` (`-c` у python) — интерпретатор, флаги, cwd (`require`/`import` от него), stdin и аргументы на месте | `'…'`, `$'…'` и `<<'EOF'` — тело доходит как набрано; `$VAR` и `${VAR}` в двойных кавычках (подстановка пути намеренная); экранированные `` \` `` и `\${` |
| `agent-model` | `Agent`/`Task` с `subagent_type` `reviewer` (`hub:reviewer`) и `model` не Opus; журнал сессии не прочитан — тоже deny | без `model` (её задаёт `reviewer.md`) и `opus`; модель, которую человек назвал в своём последнем сообщении (`transcript_path`, запись `origin.kind: human`, без вклеенных `<system-reminder>`; семейство по имени, и кириллицей: «соннет», «фейбл», «хайку»; считается упоминание в части фразы (между `, . ; : ! ? ( )` и переводами строки), где есть «ревью»/review и нет отрицания ни до, ни после: «не на sonnet», «sonnet не надо», «никакого sonnet», «sonnet-агент исследует» — не названа; ответ кнопкой AskUserQuestion — вывод инструмента, не сообщение) — решение пользователя хаба 05.11; другие агенты |
| `agent-roles` | всем — запись в `.claude/agent-memory[-local]/` репозитория (не `~/.claude/agent-memory`, уровень пользователя; удаление папки — уборка, можно); ролям `tester`/`reviewer`/`explorer` — запись в память проекта хаба (`projects/*/memory/`) и меняющий git в рабочем репозитории; `reviewer`, `explorer` — любую запись в рабочий репозиторий; `tester` — запись не в тест (`*.test.*`, `*.spec.*`, `test_*.py`, `tests/`, `__tests__/`, `fixtures/`, … — в пути от корня репозитория) | своё: scratchpad, `/tmp`, временный репозиторий там; чтение и узкий прогон тестов; основную сессию и `general-purpose` |

Рабочий репозиторий для `agent-roles` — `git rev-parse --show-toplevel` от `cwd` вызова, иначе сам `cwd`. Путь с
неизвестной переменной и относительный путь после `cd` в неизвестное место не судятся (пропуск, а не ложный блок).
Чтение git (`git tag -l`, `git apply --check`, `git stash list`, `git notes`) — не запись.

Не ловится (текстовый механизм): запись из-под другого интерпретатора — `bash -c '…'`, `python -c "open(…,'w')"`,
`find -delete`, `xargs rm`, `patch`; правка из скрипта файлом. Для ролей это ожидаемо: их граница — инструкция агента,
механизм закрывает частые прямые случаи.

## Замер на реальных вызовах (05.11, `~/hub-data/analytics/calls.db`, 56 462 Bash за 60 дней)

- `inline-script`: строгий вариант «любой `\`, `` ` ``, `${` в любом встроенном скрипте» запретил бы 2825 вызовов
  (5 %, в Linux-эпоху — 7 %) — так сессии правят файлы `python3 - <<'EOF'` каждый день, и доля ошибок у «с
  экранированием» и «без» одинакова (4,1 % и 4,5 %). Принятый вариант — только то, что переписывает shell: 112 вызовов
  (0,2 %, ≈ 2 в день в Windows-эпоху, 0 за два дня Linux). Разбор — 1,6 с на все команды, 0 ошибок, ни одной > 50 мс.
- `agent-roles` в Linux-эпоху: 0 срабатываний на 1042 вызовах ролей; в Windows-эпоху ловит реальное: ревьюер
  дописывал `.claude/agent-memory/reviewer/` и делал мутации `sed -i` + `git checkout` в дереве автора.
- `agent-model`: 33 вызова ревьюера на `fable` из ~470.
- `protect-files`: 11 записей в папки миграций из Bash — все создают новую миграцию (проходят: нет в HEAD).

## Выкат и откат

Записи на стадии `canary`: модуль работает только в проектах, чей `projects/<имя>/canary.json` перечисляет его. Порядок
(R2): проект хаба → проект B → `stage: "on"`, по рабочему дню на ступень, глядя в журнал хуков (`type=error`) и в
отказы. `hooks.json`: матчер PreToolUse теперь видит `Agent`, `Task`, `NotebookEdit` — живые сессии берут новый
матчер только при старте. Откат — `stage: "off"` в записи (сразу), либо revert; аварийно — `<хаб>/.hub-off`.
