# Хуки хаба: бриф на старте сессии

Бриф SessionStart — то, что сессия проекта получает в контекст до первого вопроса: проект, ветка, предполётная
проверка, правила из ошибок и «Дальше» последней заметки своей ветки. Вместе с файлами `CLAUDE.md` он и есть
постоянный контекст на старте (acceptance §3: v1 ≈ 49 КБ, цель ≤ 30 КБ). Библиотека — `plugin/hooks/session-start.cjs`.

## Два модуля, один обработчик `memory-brief`

| Механизм | Модуль | Стадия | Что подаёт |
|---|---|---|---|
| `memory-brief` | `sessionstart.d/10-memory-brief.cjs` | on | индекс `memory/errors-index.md` в бюджете брифа (`brief.json` `indexSections` — нужные разделы целиком, остальные строкой «по касанию») |
| `memory-core` | `sessionstart.d/11-memory-core.cjs` | canary | память v2: ядро уроков вместо индекса (срез 29) |

На каждом старте работает ровно один из них. `memory-core` подаёт бриф, если у проекта есть `memory/lessons/` и
запись `memory-core` включена: стадия `on` или `canary` с id `memory-core` (или обработчиком `memory-brief`) в
`projects/<имя>/canary.json` — та же проверка, что у раннера. Там же `memory-brief` отходит в сторону
(`session-start.cjs` `coreOn`). В проекте без `memory/lessons/` и вне канарейки бриф — прежний, побайтно.

## Бриф ядра (память v2)

```
Бриф хаба: <проект> · ветка <ветка> · изменённых N · хаб <sha>
Предполётная проверка: …                       (если есть что сказать)
Ядро уроков (memory/lessons/, status core) — действует всегда:
- <первая строка урока> [<id>]                 (≤ 15 строк)
Ядро сверх 15 — по касанию: <id>, <id>         (если уроков ядра больше)
По касанию — ещё N уроков: хук подаёт урок при касании его темы, поиск — /hub:recall. …
Последняя заметка этой ветки: memory/sessions/<файл>   (в рамке «данные из памяти»)
```

- Ядро — уроки `status: core`: фазо-независимые правила, нужные в любой сессии. Порядок: класс «одного раза»
  (`kind: once`), затем правила, знания; внутри — по дате `created` и id. Строка — первая строка урока (≤ 160 знаков) и
  его id, чтобы `recall` и счётчик повторов находили урок.
- Больше 15 уроков ядра — первые 15 строками, остальные id одной строкой «по касанию», в предполётной проверке —
  «лишние перевести в active (`/hub:memory-gc`)». Не влезает в бюджет брифа (9500 знаков с заметкой) — последние строки
  ядра тоже уходят в строку id.
- Уроки `status: active` в бриф не идут: их подают модули памяти v2 при касании ([memory-hooks.md](memory-hooks.md)),
  найти — `/hub:recall`. `retired`/`superseded` — архив.
- Урок источника «внешний» ядром не подаётся (валидатор формата и так не пускает его в ядро). Файл без frontmatter
  пропускается: порчу называет `memory-check`.
- Ядро, как и индекс, — правила проекта, без рамки; заметка ветки — данные из памяти, в рамке (решение 05.11,
  [delivery.md](delivery.md)).
- `memory/errors-index.md` в памяти v2 — выводимый экспорт (`recall export-v1`); бриф говорит его не читать.

## Двойное чтение

До среза 29 шаблон `CLAUDE.md` проекта велел «в начале сессии прочитать `errors-index.md` целиком» и «прочитать
последнюю заметку», хотя бриф уже нёс и то и другое: по журналам v1 28 из 68 сессий задач читали индекс ещё раз
(Read). Шаблон теперь говорит: правила и «Дальше» — в брифе, не перечитывать; остальное — по касанию и `/hub:recall`.
У уже созданных проектов эти строки `CLAUDE.md` правятся при выкате (память проекта правит диспетчер).

## Тематические правила (проба P5)

`.claude/rules/<тема>.md` с `paths:` Claude Code грузит по касанию пути только из корня репозитория или worktree
(`repo/.claude/rules`) и из `~/.claude/rules`; из `projects/<имя>/.claude/rules` и корня хаба — не грузит (P5,
05.11). Поэтому правило одной темы проекта — урок памяти с `when: path` (подаётся при касании) или, если
репозиторий свой, файл `repo/.claude/rules/<тема>.md`.

## Включение и откат

- Включить на проекте: `memory-core` в `projects/<имя>/canary.json` (делает диспетчер, по стадиям: хаб → проект B →
  все). Действует с нового старта сессии.
- Откат: убрать `memory-core` из `canary.json` (сразу) или `"stage": "off"` в `plugin/mechanisms/memory-core.json`;
  тогда бриф снова подаёт `memory-brief` с индексом.
- Проверки: `node --test plugin/hooks/memory-core.test.cjs`, полигон `--level hook --only '^H53'`.
